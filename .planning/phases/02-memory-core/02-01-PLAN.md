Key changes from existing stub:

1. **Change from JedisPool to Spring Data Redis:**
   - Remove direct `JedisPool jedisPool = new JedisPool(...)` constructor
   - Add `@Autowired private RedisTemplate<String, Episode> redisTemplate;`
   - Add `@Autowired private MemoryConfigurationService configService;`
   - Add `@Autowired private DataSource dataSource;`
   - Make class a proper Spring @Service with dependency injection

2. **Implement storeEpisode(Episode episode):**
   - Store to PostgreSQL via DataSource: `INSERT INTO episodes (id, session_id, content, timestamp) VALUES (...)`
   - Use redisTemplate to store in Redis HSET: `opsForHash().put("episode:" + id, "data", episode)` with Jackson serialization
   - Use redisTemplate to track time-based index: `opsForZSet().add("episodes:session:" + sessionId, id, System.currentTimeMillis())`
   - Set TTL on episode key: `expire("episode:" + id, Duration.ofSeconds(configService.getEpisodicRedisTtl()))`

3. **Implement getRecentEpisodes(String sessionId, int limit):**
   - Query Redis ZSET (reverse order for newest first): `opsForZSet().reverseRange("episodes:session:" + sessionId, 0, limit-1)`
   - Retrieve episode objects from Redis HSET using the IDs from ZSET
   - If fewer episodes returned than requested, fall back to PostgreSQL: `SELECT id, session_id, content, timestamp FROM episodes WHERE session_id = ? ORDER BY timestamp DESC LIMIT ?`
   - Combine results and return (Redis-first, PostgreSQL supplement)

4. **Implement clearExpiredEpisodes():**
   - Query PostgreSQL for episodes older than configured TTL: `DELETE FROM episodes WHERE timestamp < ?`
   - Redis expiration is automatic via EXPIRE command set in storeEpisode()

5. **Configuration source:**
   - Get TTL from configService.getEpisodicRedisTtl() (in seconds)
   - Parse from application.yml `memory.episodic.retention-days` with configurable default (30 days)

6. **Error handling:**
   - Wrap Redis operations in try/catch; if Redis fails, log warning but don't fail the write (PostgreSQL backup is durable)
   - If DataSource fails, throw RuntimeException (data loss severity)

7. **Use Spring conventions:**
   - Per project CLAUDE.md and project-conventions skill: Use @Service, @Autowired, proper Spring lifecycle
   - Follow Spring Data Redis patterns as documented in 02-RESEARCH.md "Pattern 1"
