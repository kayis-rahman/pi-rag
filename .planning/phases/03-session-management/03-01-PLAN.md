<objective>
Implement session management for Synapse to track conversations across requests with implicit session detection, automatic ID generation, and persistent storage via episodic memory.

Purpose: Users can have conversations tracked with session state persistence and automatic cleanup. Session boundaries are detected implicitly by monitoring message array patterns (decreasing length or changed earliest message), enabling compatibility with Claude Code as-is without requiring client header modifications.

Output:
- SessionManager service for orchestrating session lifecycle
- SessionDetectionStrategy component for implicit boundary detection
- AnthropicCompatibleController integration to capture sessions on every request
- Comprehensive test coverage for all session behaviors
</objective>

## Key Design Constraints (Locked Decisions)

Per 03-CONTEXT.md:
1. Session ID is auto-generated UUID on first request (no client header required)
2. Sessions detected implicitly by message array inspection:
   - New session if message count decreases (conversation reset)
   - New session if earliest message content changes (new topic)
   - Otherwise, session continues with same ID
3. Session state stored as Episode in episodic memory with sessionId field
4. Redis TTL (default 7 days, configurable) for automatic expiration
5. No explicit cleanup task needed — Redis handles it
6. Session ID returned in response header (X-Session-ID) for client reference
7. Authorization header hashed for user identification without exposing API key
