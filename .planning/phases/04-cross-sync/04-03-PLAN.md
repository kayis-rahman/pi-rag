<objective>
Add NWPathMonitor network connectivity detection and implement queue drain on network reconnect. Fix polling interval from 5s to 30s per D-12.

Purpose: When the device comes back online after being offline, buffered timer actions must be replayed to the backend in order. NWPathMonitor provides real-time connectivity detection. On network restore, it triggers drainActionQueue which replays buffered actions. The polling interval must also be corrected from 5s to 30s — polling is a fallback, not the primary sync path.

Output: TimerSyncManager with NWPathMonitor, drainActionQueue implementation, and corrected polling interval.

  <action>
    Add to TimerSyncManager class:

    Method: `private func drainActionQueue() async`

    Implementation pattern (snapshot + sequential replay with failure handling):

    1. Guard: if actionQueue is empty, return immediately
    2. Log: "Draining N queued actions"
    3. Take snapshot: `let queueSnapshot = actionQueue`
    4. Clear in-memory: `actionQueue.removeAll()`
    5. Clear persisted: `try? clearActionQueue()` (which calls KeychainStore.clear(.actionQueue))
    6. Iterate queueSnapshot sequentially with consecutive failure tracking:
       - For each queued action, build TimerActionDto from its fields (action string, phase, isRunning, remainingSeconds, workDuration, breakDuration, longBreakDuration, autoStartNextSession, shortBreaksCompleted, deviceId: self.deviceId, timestamp: queuedAction.timestamp)
       - Get access token (AuthManager.shared.getValidAccessToken(), try refresh if nil)
       - Call ApiClient.shared.pushTimerAction(dto, accessToken: token)
       - On success: reset consecutiveFailures to 0
       - On failure: increment consecutiveFailures; if >= 3, re-queue remaining actions (from current position to end) via actionQueue.append(contentsOf: remaining) and persistActionQueue(), then break
    7. After loop, log drain result

    The drainActionQueue is called from the NWPathMonitor pathUpdateHandler (Task 1) and potentially from configure() when network is available.

    Per D-05 (replay queued actions in order on reconnect), D-06 (exponential backoff with alert).

    Note: The enqueueAction method should also be wired into the sync flow. In performActionSync, if the action push fails and isNetworkConnected is false, call enqueueAction with a QueuedTimerAction built from the current timer state. But the full failure backoff integration is Plan 04 — for now, just ensure the queue mechanism works.
