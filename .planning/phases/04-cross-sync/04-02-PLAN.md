<objective>
Build offline action queuing infrastructure and fix applyEventState to perform timestamp-based conflict resolution.

Purpose: When the network is unavailable, timer actions must be buffered locally so the user can continue working without connectivity. On reconnect (or on app relaunch), queued actions replay to the backend. Additionally, applyEventState must compare timestamps before applying push state — a delayed push should not overwrite newer local state (D-01). After Plan 01 adds autoStartNextSession and shortBreaksCompleted to the push payload, applyEventState should read them from the payload instead of falling back to local values.

Output: New QueuedTimerAction.swift model, extended KeychainStore with .actionQueue, enhanced TimerSyncManager with action queue and fixed applyEventState.
</objective>

| T-04-05 | Information Disclosure | actionQueue in Keychain | mitigate | KeychainStore uses Security.framework with access group `425MSY8FLG.com.sparkage.time-beam`. iOS: kSecAttrAccessibleAfterFirstUnlock. Data is timer state (no PII, no credentials). |
| T-04-06 | Tampering | Delayed push overwriting newer state | mitigate | Timestamp comparison in applyEventState rejects stale pushes. Even if a push is delayed or replayed, it cannot overwrite newer local state. |
</threat_model>
