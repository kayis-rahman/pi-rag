## Decisions Made

- **Session completion stays local:** Timer expiry triggers local session recording + notification. No need to sync every completion to backend — the 30-second periodic poll handles state reconciliation.
- **Auto-advance is opt-in:** When autoStartNextSession is true, next phase starts automatically. When false, timer shows "00:00" on new phase until user taps start.
- **No new dependencies:** All timer infrastructure uses built-in frameworks (SwiftUI, Task.sleep, AVAudioPlayer, UNUserNotificationCenter).
- **Backend is complete:** Phase 03 is primarily iOS/macOS frontend integration work. Backend timer endpoints, services, and entities are fully implemented.
- **Flyway V1 needed:** timer_states table was created via ddl-auto: update in dev but has no Flyway migration for clean deployments.
